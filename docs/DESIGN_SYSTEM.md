# Vibe Coding Marketplace · 设计系统规范（Design System）

> 来源：`docs/PRD.md` 第 3、4、5 节（第 6 节空间界面为 3D/visionOS 规范，本产品为 2D Web，仅借鉴其思想，见 §1.1）
> 面向：Frontend Dev（前端可直接照此实现）、Backend Dev（风险动作与状态机对齐）、QA（验收对照）、Reviewer（评审对照）
> 状态词汇表唯一来源：`docs/STATUS_VOCABULARY.md`（PM 产出）；本文 §8 徽章组件仅引用该词汇表，不自行定义状态词。
> 优先级：本文是**规范**不是原型稿。所有数值（色值/字号/间距）以本文为准；组件内部不得写死色值，一律引用 token。

---

## 1. 文档信息与适用范围

- 适用页面：六功能区全部页面（Marketplace 详情/列表、上传、My Library、需求板、接单交付、钱包），以及全局导航、弹窗、Toast。
- 实现方式：**一套 token + 双模式（light/dark 自动切换）**，禁止维护两套调色板（PRD 5.4）。
- 铁律（贯穿全文）：
  1. **颜色永远不是信息的唯一载体**（§2.7）；
  2. **每个内容块都有四状态**（§3）；
  3. **低风险一步可达、高风险二次确认**（§5）；
  4. **焦点必须可见**（§7）。

### 1.1 对 PRD §6（空间界面）的借鉴说明（2D Web）

第 6 节为 3D/空间界面规范，本产品为 2D Web，**不直接适用**（60pt 点击尺寸、锚定、凝视等不采用）。可借鉴的思想并已落实到本文：

| 空间界面规则 | 本产品的 2D 落实 |
|---|---|
| 出口不能藏，允许随时退出片刻再回来 | 全局 Cancel / 返回入口常驻（Q2 §4.2、全局导航 §5.1） |
| 内容保持在视野内 | 进度与中间结果同屏（Q2 阶段性输出区 §4.2） |
| 空间 hover = 2D 可见焦点 | 键盘焦点 ring 硬性要求（§7.1） |
| 最小点击尺寸 60pt（角度） | 触控目标 ≥ 44×44pt（Web 惯例，§7.4） |
| 每个时刻最低限度的沉浸 | 默认不弹全屏遮罩，进度用面板而非全屏页 |

## 2. Design Tokens（设计令牌）

> 实现约定：CSS 自定义属性（`--token-*`），`:root` 定义 light 值，`@media (prefers-color-scheme: dark)` 与 `[data-theme="dark"]` 定义 dark 值；根元素设 `color-scheme: light dark`，让原生控件（滚动条/表单控件/日期选择器）自动适配。组件代码只引用变量名，禁止硬编码色值（建议 lint 规则）。

### 2.1 颜色语义集（light / dark 对照）

每类语义色含 4 个 token：**fill**（图标/色块填充）、**text**（文字，保证 WCAG AA）、**subtle**（浅色底/描边背景）、**border**（描边）。

| Token | Light 值 | Dark 值 | 用途 |
|---|---|---|---|
| `--color-brand` | `#4F46E5` | `#818CF8` | 主按钮、链接、选中态、进度条 |
| `--color-brand-hover` | `#4338CA` | `#A5B4FC` | 主按钮 hover |
| `--color-brand-active` | `#3730A3` | `#C7D2FE` | 主按钮按下 |
| `--color-brand-subtle` | `#EEF2FF` | `rgba(129,140,248,0.16)` | 品牌浅底（导航高亮、选中卡片） |
| `--color-on-brand` | `#FFFFFF` | `#0F1420` | 品牌色上的文字（dark 下为深字亮底，对比 6.2:1） |

|---|---|---|---|

| `--color-bg-surface` | `#F7F8FA` | `#1C1C1F` | 卡片/面板表面 |
| `--color-bg-subtle` | `#F2F3F5` | `#242427` | 次级表面（代码块、输入区） |

### 2.2 深色模式三规则（PRD 5.4 的落地）

1. **纯白降亮度**：dark 下所有原 `#FFFFFF` 的文本 → `#E6E6E6`（已入 `--color-text-primary`）；纯白底色（如空白卡片）→ `#1C1C1F`；`--color-on-brand` 例外为深字 `#0F1420`。
2. **大色块降饱和**：dark 下大面积填充不用高饱和纯色。规则：**大色块（hero 横幅、全宽色带、大面积状态底）饱和度约为 light 的 40–60%，亮度压到中性区**，或直接使用 8–16% 透明度叠底（`rgba(…,0.14~0.16)`，见各 subtle token）。示例对照：
   - light 主按钮 `#4F46E5`（白字）→ dark 主按钮 `#818CF8`（深字 `#0F1420`）；
   - light 成功色带 `#16A34A` → dark 大色带 `#1F4D33`（深绿，其上文字用 `#4ADE80`）。
   - 小面积（图标、小徽章、1–2px 描边）不受此限，可保持亮色变体。
3. **分割线用系统分隔色**：light `#E5E5EA` / dark `#3A3A3C`（已入 token），深浅自动适配；hover 边界用 `--color-separator-opaque`。**禁止**在组件里写 `#ECECEC`、`#333` 之类的自选灰。

### 2.3 文字层级

基准字号 16px；中文正文建议 15–16px，行高 1.4–1.5。所有数值成对给出（字号/行高）。

| 层级 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| Display（展示） | 32/40 | 700，-0.02em | 空态大标题、营销首屏 |
| H1（页面标题） | 24/32 | 700，-0.01em | 页面一级标题 |
| H2（区块标题） | 20/28 | 600 | 区块/卡片组标题 |
| H3（卡片标题） | 17/24 | 600 | 卡片标题、弹窗标题 |
| Body（正文） | 15/22 | 400 | 默认正文 |
| Body-sm（小正文） | 14/20 | 400 | 表单说明、列表项 |
| Aux（辅助） | 13/18 | 400 | 时间戳、脚注、徽章辅助说明 |
| Caption（注释） | 12/16 | 400 | 标签、徽章文字、版权 |
| Num（金额大字） | 22/28 | 700，`font-variant-numeric: tabular-nums` | 余额、价格、托管金额 |

字体栈：`system-ui, -apple-system, "PingFang SC", "HarmonicOS Sans SC", "Microsoft YaHei", "Noto Sans SC", sans-serif`；金额/数字一律 `tabular-nums`（防止跳动）。

### 2.6 阴影与层级（light / dark 不同方案）

**浅色模式**（真实阴影表达层级）：

| Token | 值 | 用途 |
|---|---|---|
| `--shadow-sm` | `0 1px 2px rgba(16,24,40,0.05)` | 卡片默认 |
| `--shadow-md` | `0 4px 12px rgba(16,24,40,0.08)` | 卡片 hover、下拉 |
| `--shadow-lg` | `0 16px 40px rgba(16,24,40,0.14)` | 弹窗、Toast |

**深色模式**（PRD 5.4：不用假阴影，用**边框 + 低透明度**提升层级——本方案）：

1. 层级 = **表面色阶 + 1px 边框**：`bg-app #121214` → 卡片 `bg-surface #1C1C1F` + `border 1px --color-separator` → 浮层 `bg-subtle #242427` + 边框 `--color-separator-opaque`。层级越高，表面越亮、边框越实。
2. 仅**真浮层**（弹窗/Toast/下拉）可叠加低透明度真实阴影：`0 8px 24px rgba(0,0,0,0.45)`，与边框并用。普通卡片一律无阴影、纯边框表达。
3. 深色模式禁止 `0 2px 8px rgba(0,0,0,0.6)` 之类「假立体」阴影（即暗色上加暗色，视觉无效且脏）。

### 2.7 颜色不是信息的唯一载体（硬性规则，PRD 5.4）

- **错误/成功/警告必须成对出现**：色块 + 图标 + 文字。`<p class="text-error">提交失败</p>` 单独存在 = 违规。
- 状态徽章：图标 + 文字 + 颜色三件套（§8 StatusBadge）。
- 表单校验：错误文字前必须有图标（如 `AlertCircle`），不用红框 + 变色就完事。
- 必填标记：`*` 必须配合文字（「（必填）」或 aria-label），不得只靠红色星号。
- 进度/完成差异：除颜色外，用对勾/数字/文字区分（步骤条已完成 = 对勾图标，非仅变绿）。

## 3. 四状态模式（每个内容块都要有，PRD 5.1）

> 适用范围：列表、卡片组、表单、进度面板、搜索结果、聊天/消息、上传区……**任何有内容或结果的内容块**。四个状态组件见 §8（EmptyState / Loading / ErrorBanner / Success 面板）。

### 3.1 空态 Empty

**配方（可复用 UI 结构）**：

```
┌──────────────────────────────┐
│        (图标 48px 圆底)        │
│   标题：一句说明（≤ 12 字）     │
│   副文案：怎么开始（≤ 1 句）    │
│      [ 一个明确的主按钮 ]       │
└──────────────────────────────┘
```

- 图标：48px 圆形浅底（语义色 subtle）+ 24px 语义图标；
- 文案：**一句说明 + 一个明确按钮**；说明不超过 1 句话，不解释历史，只告诉下一步；
- **只允许 1 个主按钮**（必要时 +1 个幽灵链接「查看帮助」）；
- 按钮文案是动词+对象，如「去逛逛 Marketplace」「发布第一个需求」。

**示例 1 · 空购物车（Marketplace 购买线）**

> 图标：`ShoppingCart`（info 色）｜标题「购物车还是空的」｜说明「把喜欢的作品加进来，下单后可在 My Library 在线运行或下载」｜按钮「去逛逛 Marketplace」（→ 列表页）

**示例 2 · 空需求板（Commission 需求线）**

> 图标：`ClipboardPlus`（brand 色）｜标题「还没有需求」｜说明「发布你的第一个需求，接单者会来投标」｜按钮「发布需求」（→ 发布表单，且自动填入 Q1 意图输入框）

### 3.2 进行中 In progress

规则（PRD 5.1 + Q2 精神）：

1. **>1s 阈值**：任何预计超过 1 秒的操作（检索、上传、构建、支付回调、文件处理），**立即**显示指示器——不是等 1 秒后才发现慢。预计 <1s 的操作不显示（避免闪烁）。
2. **能算百分比就算百分比**：上传（字节/文件数）、文件处理（分片数）、支付回调等可计算进度的，显示**进度条 + 百分比数字**。**禁止假百分比**（无法计算时不要编造 37%）。
3. **不能算就分步骤**：检索/构建/校验等无法算百分比的任务，用**步骤条**（§8 Stepper）显示阶段。
4. **内容区加载**：检索、列表刷新等场景，用**骨架屏**（灰色占位块，形状近似真实内容）而非全屏 spinner。
5. 百分比 ≤ 100% 封顶；进度条最小可见宽度 44px（不可见的 2px 细线不算指示器）。

**步骤条设计规格**：横向（桌面）/ 纵向（移动）；每步 = 图标 + 标签 + 一步说明（当前正在发生什么）；当前步用 spinner，完成步用对勾（`Check` 图标），未到步置灰；支持显示「第 x / y 步」。步骤条同时服务：上传审核、接单交付、Q2 四阶段（§4.2）。

### 3.3 错误 Error

**三件事（PRD 5.1）**：① 出了什么错 ② 为什么 ③ 下一步怎么办。平实语言，禁止技术黑话作为主文案（错误码只能做次级详情）。

**错误横幅模板**（组件 = ErrorBanner，§8）：

```
[icon] {出了什么错}。{为什么}。下一步：{怎么办}。      [动作按钮]
```

**文案示例**：

| 场景 | 横幅文案 | 按钮 |
|---|---|---|
| 列表加载失败 | 「加载作品列表失败。网络连接不稳定，服务器没有响应。下一步：点击重试，或检查网络后再试。」 | [重试] |
| 支付失败 | 「支付未完成。你的银行卡拒绝了这笔扣款。下一步：换一张银行卡，或联系客服。你的订单与购物车内容已保留。」 | [换卡支付] [查看订单] |
| 上传失败 | 「作品上传失败。文件超过 50MB 上限（当前 68MB）。下一步：压缩文件后重试，或改用链接导入。」 | [压缩后重试] [改用链接导入] |
| 运行校验失败 | 「作品未通过运行校验。示例在浏览器控制台报错（语法错误）。下一步：查看错误详情手动修复，或重新上传。」 | [查看错误详情] [重新上传] |

- 位置：**内容块内错误就地替换块内容**（内联横幅），页面顶部放全局错误，瞬态错误用 Toast；
- 动作按钮 1–2 个：主按钮 = 「下一步怎么办」的直接动作；
- 错误横幅必须含图标（`AlertCircle` / `AlertTriangle`，error/warning 色），不靠红字。

### 3.4 成功 Success

**给结果一个去处（PRD 5.1）**：可编辑 / 可分享 / 可撤销，至少满足其一，且必须有一个主动作把用户带到有意义的地方。

**成功页动线示例（支付成功）**：

```
┌────────────────────────────────┐
│        (CheckCircle 成功图标)    │
│          支付成功               │
│   ¥99.00 已支付，作品《xx》      │
│   已加入 My Library             │
│ [去 My Library 运行] (primary)  │
│ [下载到本地] (secondary)         │
│ [查看订单与退款政策] (link)      │
└────────────────────────────────┘
```

- **可编辑**：发布需求成功 → 「编辑需求」；上传成功 → 「继续完善描述」；
- **可分享**：需求发布成功 → 「分享给接单者 / 复制链接」；
- **可撤销**：可逆操作（取消未付款订单、删除草稿）成功 → **Toast + 「撤销」按钮，5 秒窗口**：
  > Toast：「订单已取消」+ [撤销]（5s 后消失，撤销后恢复订单为「待支付」）；
- 成功页/成功 Toast 必须给主动作，不能只显示「成功」两个字就完事。

## 4. Q1 / Q2 / Q3 交互模式（PRD 第 3 节 · 评分重点）

### 4.1 Q1 意图表达（How is intent expressed）

禁止：空输入框 +「What would you like to do?」。

**① 输入框内 3 个可点击示例（点击即填入）**

```
┌──────────────────────────────────────────────┐
│  描述你想做的事…                                │
│  [chip] [chip] [chip]  ← 输入框内底部一行       │
└──────────────────────────────────────────────┘
```

- 位置：输入框**内部底部**（不是输入框下方外部），始终可见；
- 规格：3 个 chip（胶囊按钮），每个 ≤ 24 字，一行放不下自动换行（最多 2 行）；
- 交互：点击 chip → **填入输入框**（替换当前内容）、光标移到末尾、聚焦输入框、**立即启用提交按钮**；chip 也是真按钮（可 Tab 聚焦）；
- 示例内容（真实产品场景，前端照抄）：
  1. 「找一个 200 元以内、能离线玩的益智小游戏」
  2. 「买一个 Markdown 笔记工具，支持导出 PDF」
  3. 「发布需求：7 天内做一个打卡小程序，预算 500–800 元」

**② 最多 2 个澄清追问（3 个以上 = 系统愚蠢）**

- 形式：**内联追问卡**（非模态弹窗，不打断上下文），出现在输入框正下方；
- 结构：标题「还需要确认 2 个问题」+ 进度「问题 1 / 2」+ 当前问题 + 选项 chips + 「其他（自由输入）」；
- 规则：一次只问 1 题；每题给 2–4 个选项 chip + 自由输入；**第 2 题答完必须停止追问**——若信息仍不足，按已有信息执行，并在确认卡中标注假设（「我按 500 元以内理解，可在确认页修改」）；
- 触发条件：提交内容缺关键参数（预算 / 品类 / 时间线 / 范围）时才追问；已有足够信息则**跳过追问直接进确认步骤**。

**③ 系统理解意图 → 用户确认 → 执行（确认步骤 UI 模式）**

```
┌──────────────────────────────────────────┐
│  我理解你的意图                            │
│  (icon) 意图类型：购买作品                  │
│  参数：[品类: 益智小游戏] [预算: ≤¥200]      │
│        [可离线: 是]                        │
│  将为你：下单 ¥199 + 手续费 ¥10 = ¥209     │
│  [确认，开始] (primary)  [修改] (secondary) │
└──────────────────────────────────────────┘
```

- 展示：意图类型图标 + 名称、解析出的关键参数（chips）、将执行的动作 + 费用/风险摘要；
- 按钮：`[确认，开始]`（primary，文案含动作词）/ `[修改]`（secondary，回到输入并保留已填内容）/ `[取消]`（ghost）；
- **确认前绝不执行**；确认后进入 Q2 进度面板；
- 高风险意图（下单 / 支付 / 提现 / 下架）在确认卡内直接展示费用汇总与风险说明；若命中 §5 高风险规则，确认后**再叠加二次确认弹窗**。

### 4.2 Q2 进度可见（How is progress visible）

禁止：一个转圈 +「Generating…」。

**① 四阶段步骤指示器（固定顺序，全产品统一）**

| 步骤 | 标签 | 说明文案模板 | 图标 |
|---|---|---|---|
| 1 | 理解意图 understanding | 「正在理解你的意图…」 | `Brain` |
| 2 | 检索 retrieving | 「正在检索可用的作品与素材…」 | `Search` |
| 3 | 构建 building | 「正在构建 / 组合你的作品…」 | `Wrench` |
| 4 | 校验 checking | 「正在校验运行与验收标准…」 | `ShieldCheck` |

- 规格同 §3.2 步骤条：横向（桌面）/ 纵向（移动）；当前步 spinner、完成步对勾、未到步置灰；
- 每阶段都有**说明文案**（正在发生什么），不只放阶段名；
- 阶段不加速任何东西，但显著降低中途放弃率（PRD 事实）——前端不要试图跳过阶段展示。

**② 尽早放出中间结果（阶段性输出区）**

- 进度面板结构：`顶部 = 阶段步骤条 + Cancel 按钮`；`主体 = 阶段性输出区`；
- 阶段性输出区规则：**有中间结果立刻渲染，绝不让用户盯着空转圈**——
  - retrieving 完成 → 立刻渲染候选列表（骨架占位 → 逐条填入）；
  - building 完成 → 渲染预览（截图/可运行 iframe 草稿）；
  - checking → 逐项勾选清单（验收标准、运行检查项，一项完成勾一项）；
- 已产出的中间结果**保留在面板内不回退**（也是 Q3「保留已完成内容」的基础）。

**③ Cancel 按钮始终可用**

- 位置：进度面板**右上角常驻**，全局同位置（桌面）/ 进度条上方（移动）；
- 样式：danger-ghost（`--color-error-text` 文字 + 无底），文案「取消」；
- 禁用规则：默认**始终可用**；唯一例外 = 不可中断的原子提交（如支付回调等待，通常 ≤ 数秒），此时按钮短暂禁用并显示「正在提交，请勿关闭」；
- 取消行为：可逆任务（生成/检索类）直接取消 → 提示「已取消，保留已生成内容（见下方）」；不可逆丢弃 → 轻量确认：「将放弃本次生成，你输入的内容已保存。要取消吗？」`[继续]` `[取消生成]`；
- 取消后用户可随时重新开始，且草稿不丢失（Q3 保障）。

### 4.3 Q3 失败恢复（How do you recover from failure）

禁止：「Something went wrong, please try again」。

**① 失败卡片设计（哪一步失败 + 为什么，平实语言）**

```
┌──────────────────────────────────────────┐
│ (!) 第 3 步「构建」失败                     │
│ 运行环境缺少 node-canvas 依赖（版本不兼容）， │
│ 构建无法完成。                              │
│ ── 已保留的内容 ──────────────────          │
│ ✓ 检索到的 3 个候选作品（已列在下方）        │
│ ✓ 你输入的需求草稿                          │
│ [重试] (primary)  [换一种方式] (secondary)   │
│ [手动编辑] (ghost)                         │
└──────────────────────────────────────────┘
```

- 头部：错误图标 + **哪一步失败**（直接引用步骤条阶段名，如「第 3 步『构建』失败」）+ **为什么**（平实语言，禁止黑话作主文案）；
- 组件：FailureRecoveryCard（§8）。

**② 保留已完成内容的视觉表达**

- 区块标题「已保留的内容」+ 说明「以下内容不会丢失」；
- 视觉：区块左侧 3px 品牌/成功色竖边 + subtle 底色 + 逐项 `Check` 对勾列表 + 内容摘要（真实内容，不是「有内容」四个字）；
- 铁律：**失败后不整页刷新、不丢用户输入**；草稿（输入框内容、检索结果、上传文件）本地持久化（`localStorage` / 组件状态提升），失败恢复时原样还原——**这是三题里工程最重的一题**，前端必须为每个长流程设计草稿持久化。

**③ 三条出路（按钮层级设计）**

| 出路 | 按钮样式 | 行为 |
|---|---|---|
| 重试 | **primary**（唯一主按钮） | 用相同参数重新执行，不重头再来 |
| 换一种方式 | secondary（描边） | 换策略：换检索词 / 改文件上传 / 换支付方式 / 换构建方式 |
| 手动编辑 | ghost / link | 打开保留内容的可编辑视图（草稿编辑器） |

- 层级规则：**一个 primary、一个 secondary、一个 ghost，三按钮不同权**，禁止三个等大按钮平铺；
- 补充：自动重试最多 1 次（静默重试 1 次后必须展示失败卡片），禁止无限自动重试。

## 5. 风险等级 UX 规格（PRD 第 4 节）

> 一行检验法：**用户误触之后，能不能自己退回来？退不回来，这个动作就必须做得难。**

### 5.1 低风险动作：一步可达

| 动作 | 规格 |
|---|---|
| 试玩项目 | 详情页内嵌试玩区，**免登录、免付款、点开即玩**；试玩不要求任何账号状态；「下载/购买」才需要登录，试玩永远不需要 |
| 查看总价 | 下单页**一屏**显示：作品价 + 手续费（注明费率，如 5%）+ 实际应付总额，下单前实时计算，任何支付动作之前可见 |
| 取消未付款订单 | **一步完成**：订单卡片上一个「取消订单」按钮，点击即取消；**不追问原因、不弹二次确认**（可逆动作）；成功后 Toast + 「撤销」5 秒 |
| 两步回 My Library | 见下方「全局导航方案」 |
| 联系卖家 / 举报 | **常驻详情页**操作行，不藏进三级菜单（见下方） |

**全局导航方案（任何页面两步回 My Library，PRD §3）**：

- 桌面：顶栏常驻 `[Logo] [Marketplace] [需求板] [钱包] [My Library] [头像]`——**Library 入口永远渲染在顶栏可视区**，不折叠进汉堡菜单、不随页面滚动隐藏；
- 移动：底部 TabBar 五项：`Marketplace / 需求板 / Library / 钱包 / 我的`，Library 固定位置；
- 校验标准：任意页面（含详情、弹窗、全屏流程页）**≤ 2 次点击**到达 My Library（例：弹窗内 → 关弹窗 1 次 → 点顶栏 Library 第 2 次 ✓）；
- 面包屑：次级页面提供「← 返回 Library」路径。

**联系卖家与举报常驻**：详情页操作区固定一行 `[联系卖家] [举报] [···]`，两个入口**永不在折叠菜单内**；举报点击后即弹标准举报表单（内容块四状态齐全）。

### 5.2 高风险动作：二次确认

| 动作 | 规格 |
|---|---|
| 大额充值 | **二次确认弹窗**：标题「确认充值」+ 当前余额 → 充值金额 → **充值后余额**（两数并列展示）→ 到账说明；按钮 `[确认充值 ¥500]`（文案含金额）/ `[取消]`。触发阈值：单次充值 ≥ ¥500（阈值可配置，写入同一 token/常量）。弹窗内金额用 `--text-num` + tabular-nums |
| 确认收货并放款 | **先看交付物再确认**流程：① 买家点「确认收货」→ 进入**交付物预览页**（展示交付内容 + 验收标准 checklist 逐项对照，可下载/试运行）；② 看完后出现最终二次确认弹窗：「确认收货后 ¥500 将从托管账户放款给接单者，**此操作不可撤回**」`[确认放款]` `[返回检查]`。**未预览交付物时「确认放款」按钮不可用** |
| 提现 | 验证流程：身份验证（实名信息）+ 银行卡验证（卡号/持卡人/开户行）+ 提现金额 + 手续费 → **二次确认弹窗**展示：提现金额、手续费、**实际到账金额**、**到账时间**（如「T+1 工作日 18:00 前到账」）→ `[确认提现]`。到账时间必须明确写出，不得写「尽快」 |
| 下架已售作品 | 下架表单**必填理由**（选项单选 + 补充说明 textarea）+ 后果说明：「已购买家保留访问权（运行/下载不受影响），新买家不可再购买」→ 二次确认弹窗 |
| 修改验收标准 | 一旦有人接单，**不可单方面修改**。锁定状态的视觉表达：字段旁 `Lock` 锁图标 + 说明文字「已有接单者投标，验收标准已锁定，不可修改」+ 字段只读（无编辑入口、无 hover 编辑态、底色不变）；tooltip 补充「如需变更，请联系接单者协商，双方同意后由平台记录变更」。未接单前正常可编辑 |

**二次确认弹窗通用规格**（组件 ConfirmDialog，§8）：遮罩 + 居中弹窗（radius-xl、focus 陷阱、Esc = 取消）；必须展示**动作后果**（余额变化 / 到账时间 / 不可逆提示）；确认按钮文案 = 动词 + 对象（「确认放款」「确认充值 ¥500」），禁止裸「确定」。

## 6. 反馈三通道（PRD 5.3，可叠加）

### 6.1 视觉（系统图标集）

- **推荐：lucide（lucide-react / lucide 包）**，备选：heroicons。
- 理由（lucide）：MIT 开源可商用；1300+ 图标统一 24px 网格、统一 2px 描边，**语义一致**（同概念只有一种画法）；tree-shakable、按需打包；官方 React/Vue 绑定；支持 `aria-hidden` 默认与 `aria-label` 覆盖，无障碍友好。
- 使用规则：默认 24px、`stroke-width: 2`；**一个项目只用一套图标集，禁止混用**；状态/语义图标必须配文字（§2.7）；交互图标（按钮内图标）必须可聚焦且有 `aria-label`；纯装饰图标 `aria-hidden="true"`。
- 状态图标映射：成功 `CheckCircle` / 警告 `AlertTriangle` / 错误 `AlertCircle` / 信息 `Info`；空态见 §8。

### 6.2 触觉（Web 可行性说明）

- Web 上唯一原生触觉通道：**Vibration API（`navigator.vibrate()`）**。
- 可行性：✅ Chrome / Android 全支持；❌ iOS Safari 与桌面浏览器**不支持**（调用安全失败，需特性检测）；⚠️ 需用户交互后才有权限（与 autoplay 策略一致）。
- 实现规格（移动端渐进增强，特性检测后调用）：

| 事件 | 震动模式 |
|---|---|
| 成功 | `vibrate(30)`（单次轻震） |
| 警告 | `vibrate([20,40,20])` |
| 失败 | `vibrate([50,80,50])` |

- **永不作为唯一通道**：触觉永远与视觉/文字成对出现；桌面端无触觉时，用微动效近似（按压 `transform: scale(0.98)`、失败抖动动画）——注明这是视觉近似，不是触觉。

### 6.3 声音（慎用，永不当唯一通道）

- **默认静音**（不自动发声），提供全局「音效开关」（默认关）；
- 若启用：成功 = 短促柔和提示音（≤ 300ms），错误 = 明显不同音色；**任何声音必须伴随视觉反馈**；
- 用户多半静音（PRD 事实），音频 0% 完成度不得影响可用性。

## 7. 无障碍底线（PRD 5.5）

### 7.1 焦点可见（focus ring，硬性要求）

| Token | Light 值 | Dark 值 |
|---|---|---|
| `--color-ring` | `#6366F1` | `#A5B4FC` |

- 规格：`outline: 2px solid var(--color-ring); outline-offset: 2px;`（可加 `box-shadow: 0 0 0 4px rgba(99,102,241,0.35)` 软晕增强可见性）；
- 触发：**只对 `:focus-visible`**（键盘/辅助技术导航显示，鼠标点击不显示）；
- 对比：ring 色与相邻背景对比 ≥ 3:1（light `#6366F1` 与白底、dark `#A5B4FC` 与 `#121214` 均满足）；
- 应用范围：所有可交互元素（链接、按钮、输入框、chip、整卡可点击的卡片、步进器、Tab）。**2D 的 focus ring = 空间界面的 hover（PRD §6 借鉴）**。

### 7.2 禁用按钮清晰可读 + 附说明（禁用 ≠ 看不见）

- 禁用态视觉：底色 `--color-bg-subtle` + 文字 `--color-text-disabled`（对比 ≥ 3:1，比常规禁用更可读）+ 保留边框；`cursor: not-allowed`；
- **必须附说明**：禁用原因以文字呈现于按钮旁或 tooltip：
  - 「验收标准已锁定，不可修改」（§5.2）；
  - 「未选择交付物，无法确认放款」；
  - 「输入不完整：还差预算区间」；
- 禁止只用灰底灰字让人猜；禁用控件本身不接收焦点（`disabled`），原因说明可聚焦。

### 7.3 对比度（WCAG AA 参考）

- 正文 ≥ 4.5:1；大文本（≥ 18.66px 粗体 或 ≥ 24px）≥ 3:1；UI 组件与图形 ≥ 3:1；
- 关键组合已内建于 token（本规范已核算）：`brand #4F46E5` 在白底 6.3:1 ✓；dark 主按钮 `#818CF8` + 深字 `#0F1420` 6.2:1 ✓；`text-primary dark #E6E6E6` 在 `#121214` 14.7:1 ✓；light 语义文字用深变体（success `#15803D`、warning `#B45309`、error `#B91C1C`、info `#0369A1`）均 ≥ 4.5:1 ✓；
- 前端在引入新色值时按 AA 核对，禁止引入低于阈值的组合（尤其是「浅底 + 浅字」）。

### 7.4 触控目标

- 可交互元素命中区域 ≥ **44×44pt**（移动端按钮可视高 40px 可接受，但 padding/命中区必须 ≥ 44×44）；列表行、chip、步进器点击项同理。

| 5 | **EscrowStatusBar** 托管状态条 | 交易详情、接单详情 | 展示：交易金额、当前阶段（托管中→已放款）、当前持有方（买家/平台/接单者）、预计到账时间；嵌入 StatusBadge | 语义色+图标+文字+时间戳 | 三要素齐全；时间明确写 |
| 6 | **IntentInput** 意图输入框 | 首页、需求发布 | 输入框 + 3 个可点击示例 chip（点击即填）+ ≤2 追问内联卡 + 理解确认卡（展示→确认→执行） | §4.1 全部规格 | chip 是真按钮可聚焦；确认卡信息可读 |
| 7 | **FailureRecoveryCard** 失败恢复卡片 | 任意异步任务失败处 | 哪步失败+为什么 + 已保留内容区 + 三出路（重试 primary / 换一种方式 secondary / 手动编辑 ghost） | §4.3 | 错误图标+文字；保留区可滚动 |
| 8 | **ConfirmDialog** 二次确认弹窗 | 大额充值、确认放款、提现、下架 | 标题+动作后果（余额变化/到账时间/不可逆提示）+ `[确认+动作]` `[取消]`；focus 陷阱、Esc 取消 | §5.2 | 确认按钮文案含动作与金额；焦点入弹窗 |
| 9 | **EmptyState** 空态 | 购物车、需求板、搜索结果、消息列表 | 图标+一句说明+1 个明确按钮 | §3.1 | 图标 aria-hidden；按钮文案明确 |
| 10 | **ErrorBanner** 错误横幅 | 内容块内/页面顶部/表单 | 图标+出了什么错+为什么+下一步+1–2 个动作按钮；块内错误就地替换块内容 | §3.3 模板 | 图标+文字成对；可聚焦关闭 |

## 9. 六功能区页面级设计要点

### 区域 1 · Marketplace 与详情页（作品交易线）

1. 列表页：分类筛选（sticky 顶部）+ 卡片网格（桌面 4 列），封面/价格/作者/评分全部直接可见；
2. 详情页**必须可直接试玩**（内嵌 iframe/播放器，免登录免付款）——不是封面图轮播；
3. 详情页操作行常驻 `[试玩] [联系卖家] [举报]`（§5.1），不藏菜单；
4. 下单前总价（含手续费）一屏可见（§5.1）；订单卡片支持一步取消 + 撤销 Toast；
5. 评分与试用范围（trial scope）展示清晰，试用范围边界文案明确。

### 区域 2 · 上传与上架

1. 拖放区四状态齐全：空态（拖入 HTML 文件）/ 进行中（百分比+字节数）/ 错误（超限原因+换方式）/ 成功（下一步按钮）；
2. 审核进度全程可见（Stepper：上传 → 审核中 → 上架中 / 驳回），作者最关心「我的作品到哪一步了」；
3. 定价：免费/定价切换；定价时显示平台手续费与到手金额预估；
4. 草稿自动保存（Q3 保障）：标题/描述/定价输入即存，刷新不丢；
5. 被驳回时失败卡片三出路：重试（修改后重传）/ 换一种方式（链接导入）/ 手动编辑草稿。

### 区域 3 · 购买与 My Library

1. 全局导航 Library 常驻，任意页面 ≤ 2 步可达（§5.1 方案）；
2. 已购内容：在线运行或下载，两个动作都直接可见；
3. **退款路径必须存在且可被找到**：订单详情内常驻「退款政策」入口与「申请退款」；
4. 订单状态徽章与交易详情状态一致（同一状态词）；
5. 空态：My Library 空时 → 「去逛逛 Marketplace」引导购买。

### 区域 4 · 发布需求 Commission

1. 发布表单顶部用 IntentInput 辅助（Q1 三示例含需求场景），降低填写门槛；
2. **验收标准发布时锁定**：发布前可编辑，有人接单后锁图标+说明（§5.2 视觉规格）；
3. 字段：预算区间、时间线、验收标准、参考作品，全部必填校验带图标+文字；
4. 需求板可筛选：状态 / 分类 / 预算区间；卡片显示状态徽章与投标数；
5. 空需求板 → 空态引导「发布第一个需求」（§3.1 示例 2）。

### 区域 5 · 接单与交付

1. 状态流 Stepper：投标 → 被选中 → 进行中 → 里程碑提交 → 买家验收 → 结算；**买卖双方看到同一状态词**（StatusBadge 单一来源渲染）；
2. 里程碑提交 = 交付物 + 验收标准 checklist 对照展示；
3. **确认收货先看交付物**（§5.2 流程），未预览不可放款；
4. 托管状态条（EscrowStatusBar）展示金额/持有方/预计到账；
5. 接单详情页常驻「联系买家」入口与消息记录。

### 区域 6 · 钱包与充值（连接两条线的钱）

1. WalletBalanceCard 顶部两栏：**钱在谁手里 / 何时到账**一眼可见（§8 组件 4）；
2. 充值：小额直接提交；**大额（≥¥500）二次确认**并显示充值后余额（§5.2）；
3. 提现：身份+银行卡验证 + 到账时间注明（T+1 等）+ 二次确认弹窗（金额/手续费/实际到账）；
4. 收支记录：可筛选（充值/消费/托管/退款/提现），金额 tabular-nums；
5. 托管状态条与订单详情联动：放款后余额与托管金额实时反映。
