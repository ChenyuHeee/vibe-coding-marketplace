## 1. 产品定义

**Vibe Coding project marketplace**：一个交易「能运行的作品（vibe coding 项目）」的在线市场。

- 三种角色共用一个平台：**买家 buyer**（买作品、发需求）、**卖家 seller**（上传出售作品）、**接单者 contractor**（投标接单）。
- 同一个页面，对三种角色呈现不同内容；**三种角色的状态词汇表必须完全一致**（同一个状态词，三种角色看到的是同一件事的不同侧面）。
- 卖的是**能运行的东西**，不是图片：详情页必须可以直接试玩。

---

## 2. 六大功能区（全部必做）

### 区域 1 · Marketplace 与详情页（作品交易线）

- 列表页：分类筛选（category filters）、封面截图、价格、作者、评分。
- 详情页：**必须能直接运行/试玩**（不是封面图轮播）；含价格、作者、评分、试用范围。

### 区域 2 · 上传与上架

- 作者**拖入 HTML 文件**即可上架；填写标题、描述；定价或免费；选择试用范围（trial scope）。
- 审核流程：作者全程能看到**审核进度**（作者最想知道的就是「我的作品到哪一步了」）。

### 区域 3 · 购买与 My Library

- 流程：下单 → 支付 → 收到作品 → **在线运行或下载**。
- **退款路径**必须存在且可被找到。
- 已购内容：从**任何页面两步之内**回到 My Library（two steps back to My Library from any page）。

### 区域 4 · 发布需求 Commission（需求线）

- 发布字段：预算区间、时间线（timeline）、**验收标准（acceptance criteria）**、参考作品（reference works）。
- 需求板（commission board）**可筛选**。
- ⚠️ **验收标准字段在发布时即锁定**（fixed at posting time）——它是之后所有纠纷的源头，不允许事后修改。

### 区域 5 · 接单与交付

- 状态流：投标（bid）→ 被选中（selected）→ 进行中（in progress）→ 里程碑提交（milestone submission）→ 买家验收（buyer acceptance）→ 结算（payout）。
- **买卖双方必须看到同一个状态**（同一笔交易，两边屏幕上的状态词一致）。

### 区域 6 · 钱包与充值（连接两条线的钱）

- 功能：余额（balance）、充值（top-up）、支出与收入记录、提现（withdrawal）、**托管状态（escrow status）**。
- 两个问题必须一眼可见：**钱现在在谁手里**、**何时到我的账户**。

> 结构逻辑：1–3 是「作品交易线」，4–5 是「需求线」，6 是连接它们的钱。

## 3. 三个必答题（设计每个界面时逐一回答）

### Q1 · 意图如何表达（How is intent expressed）

- ❌ 禁止：空输入框 + 「What would you like to do?」
- ✅ 要求：
  - 输入框内放 **3 个可点击示例**，点击即填入；
  - 信息不足时**追问最多 2 个问题**（3 个以上用户会判定系统愚蠢）；
  - 展示系统**理解到的意图**，让用户**确认**后再执行。

### Q2 · 进度如何可见（How is progress visible）

- ❌ 禁止：一个转圈 + 「Generating…」
- ✅ 要求：
  - **分阶段展示**：understanding → retrieving → building → checking；
  - 尽早放出**中间结果**；
  - **随时可取消**（Cancel 按钮始终可用）。
  - 事实：分阶段不会更快，但显著降低中途放弃率。

### Q3 · 失败如何恢复（How do you recover from failure）

- ❌ 禁止：「Something went wrong, please try again」（一行红字 + Retry）
- ✅ 要求：
  - 说清**哪一步失败、为什么**（平实语言）；
  - **保留已完成的内容**，不重头再来（这是三题里工程最重的一题）；
  - 提供**三条出路**：重试 / 换一种方式 / 手动编辑。

## 4. 核心原则：动作的风险等级决定其难度

> 一行检验法：**用户误触之后，能不能自己退回来？退不回来，这个动作就必须做得难。**

**做到极容易（可逆、降风险）：**

- 试玩项目：免登录、免付款、点开即玩；
- 查看总价：下单前一屏显示实际应付总额（含手续费）；
- 取消未付款订单：一步完成，不追问原因；
- 找到已购作品：任何页面两步回 My Library；
- 联系卖家与举报：常驻详情页，不藏进三级菜单。

**故意做难（不可逆、产生风险）：**

- 大额充值：**二次确认**，并显示确认后的余额变化；
- 确认收货并放款：一键放款前必须让用户先看到交付物；
- 提现：身份 + 银行卡验证，并**注明到账时间**；
- 下架已售出的作品：必须给出理由，且已购买家保留访问权；
- 修改验收标准：一旦有人接单，**不可单方面修改**。

## 5. 设计系统规则（所有页面适用）

### 5.1 四种状态（每个内容块都要有）

1. **空态 Empty**：首次启动什么都没有——教用户怎么开始（一句说明 + 一个明确按钮）；
2. **进行中 In progress**：超过 1 秒的操作给指示器，能算百分比就算百分比，不能就分步骤；
3. **错误 Error**：说三件事——出了什么错、为什么、下一步怎么办；
4. **成功 Success**：给结果一个去处——可编辑、可分享、可撤销。

### 5.2 Apple 八原则

- **做作业时先跑前四条**（关于你和用户的关系）：**Purpose**（先想清楚对这群人什么最重要）、**Agency**（让人按自己的方式做事，知道正在发生什么，能反悔）、**Responsibility**（为使用者利益行事，安全隐私，说人话）、**Familiarity**（建立在人们已知的基础上，全程一致）。
- **交作业前跑后四条**（关于你和工作的关系）：**Adaptability**（适应不同场景/设备/输入方式）、**Simplicity**（清晰直接，每个元素都要挣到自己的位置）、**Craft**（每个细节都见用心）、**Delight**（给一点人情味，人记住的是感受）。

### 5.3 反馈三通道（可叠加）

- **视觉**：用系统图标集（语义一致的矢量图标）；**触觉**：成功/警告/失败不同触感（人没看屏幕时唯一能到达用户的通道）；**声音**：慎用，永远不能是唯一通道（用户多半静音）。

### 5.4 色彩与深色模式

- **颜色不能是信息的唯一载体**（红字错误必须配图标或文字——色盲用户）。
- 深色模式 ≠ 反色；纯白文字在深色模式要降亮度；大色块降饱和（否则夜间刺眼）。
- 分割线用系统分隔色（深浅模式自动适配），不要自选浅灰；一套代码适配两种模式，而不是维护两套调色板。

### 5.5 无障碍底线

- 焦点必须可见（2D 的 focus ring / 3D 的 hover effect 是**硬性要求**）；
- 禁用按钮仍然清晰可读，并附说明（禁用≠看不见）。

## 6. 空间界面规则（若产品含 3D/空间界面，按 visionOS 规范）

- **输入**：凝视（gaze）只做定位，**只有捏合（pinch）才触发**；凝视数据对应用保密（应用只知道捏合时选了什么）。
- **Hover 必做**：空间里唯一表示「当前选中」的手段；三条限制：变化要轻微（亮度/高度即可）、**高亮区域必须等于点击区域**、不许当动画秀场。一句话：空间 hover = 2D 的可见焦点。
- **最小点击尺寸 60pt**（≈2.5° 视角，1 米处约 4.4cm；对比 iPhone 44pt）。它是**角度**不是物理尺寸——放得越远要放得越大。
- **放置**：默认距离 1–2 米；高度在眼睛自然落点、略低于地平线；锚定三选一——**world-lock（默认）** / body-lock（慎用） / head-lock（避免）。
- **材质**：半透明玻璃（保持方位感、自适应环境亮度、不用假阴影表达层级）。
- **沉浸**：默认共享空间（shared space）；**每个时刻用最低限度的沉浸**——不要一上来全沉浸（新手最常见错误）。
- **舒适五硬规则**：内容保持在视野内（相对头部定位）；避免压迫/突动/过快/无静止参照的运动；支持手放在腿上/身侧的间接手势；直接手势时内容要近、姿势不持久；全沉浸时不要鼓励大动作。
- **退出**：出口不能藏——用户在里面迷向会恐慌，必须允许随时退出片刻再回来，而不是要求不间断停留。
- 安全通告：驾驶/操作重型机械时禁用；不安全环境中禁用；**仅限 13 岁以上**。

## 7. 交付与自检清单

- 交付物：系统内可演示、可分享的**动手链接**（课堂参与分），另交 Discussion 2 卡片（三种锚定各给 1 个适用场景 + 1 个失败场景）。
- 提交前逐项自查：

- [ ] 六功能区全有、三角色全走通
- [ ] 状态词三角色一致（同一状态词两边看到同一件事）
- [ ] 详情页可试玩；My Library 任意页面两步可达
- [ ] 验收标准发布时锁定；托管状态与到账时间一眼可见
- [ ] Q1 三示例 + ≤2 追问 + 确认意图；Q2 分阶段进度 + 可取消；Q3 保留已完成 + 三条出路
- [ ] 低风险动作一步可达；高风险动作二次确认（对照第 4 节清单）
- [ ] 每个内容块四状态齐全；反馈有视觉+触觉
- [ ] 前四原则（做时）与后四原则（交前）各跑一遍
- [ ] 颜色非唯一信息载体；焦点可见
- [ ] 链接他人设备可打开
